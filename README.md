````markdown\n```markdown\n# QR (admin-protected encoder + passphrase-protected decoder)\n\nThis Next.js app provides:\n- A serverless /api/encode endpoint protected by ADMIN_TOKEN (server checks Authorization: Bearer <ADMIN_TOKEN>).\n- An admin UI at /encode to create encrypted QR payloads.\n- A public decoder at /decode which accepts an encrypted blob (?q=<base64>) and decrypts client-side when the correct passphrase is provided.\n\nSecurity model (recommended):\n- ADMIN_TOKEN is a strong random secret stored in Vercel environment variables. Do NOT commit it to the repo.\n- Per-QR passphrase is provided by the encoder (you) and is not stored by the server. The scanner must know the passphrase to decrypt.\n- If you want automatic decode (no user passphrase entry), note that embedding the passphrase inside the QR is less secure and not recommended.\n\nDeploy to Vercel:\n1. Create a project in Vercel from this repository.\n2. In Project Settings -> Environment Variables, set:\n   - ADMIN_TOKEN : <a strong random string>\n3. Deploy.\n\nUsage:\n- Visit /encode, paste your ADMIN_TOKEN into the input (the UI keeps it only in your browser), set payload JSON and a per-QR passphrase, then click "Encode & Generate QR".\n- Scan the generated QR. The QR encodes a compact base64 blob. The scanner opens /decode?q=<base64> (or paste the blob) and must enter the passphrase to decrypt and reveal the payload.\n\nNotes:\n- Do NOT commit real secrets. Use the Vercel environment variable editor for ADMIN_TOKEN.\n- If you prefer OAuth-based admin auth or server-side decryption flows, we can extend the design.\n```\n````
